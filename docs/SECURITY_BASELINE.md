### 已知的信任模型问题（待阶段 1 处理）

把一张**终端实体证书**（无 CA 标志）加入“受信任的根证书颁发机构”，
在密码学语义上属于“把叶子证书当作信任锚”的权宜做法：
Windows 能通过验证，但这不等价于一张正式的代码签名 CA 证书。
阶段 1 将明确说明该做法的范围与替代方案，并避免夸大其安全效果。

## 已知限制（基线时点）

1. 仅支持 Microsoft Store（MSIX）版 Codex。
2. 接管裸启动实例需要重启 Codex，约 20～40 秒。
3. 自签名证书不等同公共代码签名证书，SmartScreen 仍可能警告。
4. 更新流程当前直接拉取上游 `main` 分支，未固定 commit（阶段 3 处理）。
5. 卸载脚本尚未提供“彻底卸载（含证书清理）”分支（阶段 5 处理）。
6. 日志可能记录本机绝对路径（阶段 4/6 处理脱敏）。
7. CI 产物使用每次构建时生成的临时自签名证书，**不应视为官方签名发布物**（阶段 1 说明）。
