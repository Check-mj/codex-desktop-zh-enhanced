# 运行时行为与测试记录（RUNTIME BEHAVIOR）

> 本文记录启动器关键运行时行为的**实测结果**（阶段 4）。测试环境：
> Windows 11 10.0.26300 / Codex Desktop 26.1013.4894.0（MSIX）/ 普通用户权限。
> 测试日期：2026-10-18 ~ 2026-10-19。

## 1. 调试接口（CDP / Inspector）

### 实测事实

- Codex 由启动器启动时，参数包含：
  `--remote-debugging-address=127.0.0.1 --remote-debugging-port=<随机端口> --inspect=127.0.0.1:<随机端口>`
- 端口通过 `TcpListener(IPAddress.Loopback, 0)` 预留随机端口，仅绑定回环地址。
- 实测 `Get-NetTCPConnection`：渲染调试端口监听在 `127.0.0.1`，**未监听 0.0.0.0/局域网地址**。
- inspector 端口在当前 MSIX 版本连接失败（原生菜单补丁因此不生效，仅日志报错），已有记录。
- **调试端口在 Codex 运行期间持续开放**（Chromium 无法在运行中关闭该端口）。

### 风险说明（如实记录）

> 只要 Codex 由启动器启动并保持运行，本机同用户权限的任意进程都可以连接该回环调试端口，
> 进而读取/修改 Codex 渲染进程的页面状态。这是当前注入架构的固有代价，不是"已修复"的问题。

当前缓解措施：
- 只绑定回环地址（不可被局域网访问）；
- 端口随机；
- 仅在用户主动启动/开机自启时开启，不额外常驻更多端口。

可能的后续改进（未实现，需评估对汉化能力的影响）：
- 会话结束后重启 Codex 以关闭调试端口（会丢失运行时注入，需要重新注入）；
- 评估 `--remote-debugging-pipe` 等替代方案（Electron 当前版本支持情况未验证）。

### 未测试项

- [ ] 端口在异常退出后的残留（当前依赖进程退出释放）。

## 2. 进程守护行为

| 场景 | 预期 | 实测结果 |
|---|---|---|
| 登录后启动（无 Codex） | 约 2 秒后自动以中文启动 Codex | ✅ `guard.autolaunch` |
| 启动器重启时 Codex 已在运行 | 本次不再自动拉起（避免用户关闭后又被重开） | ✅ `guard.autolaunch.skipped existing-instance`（v0.8.0 修复） |
| 用户主动关闭 Codex | 守护不重新打开 | ✅ 关闭后 12 秒无新进程 |
| Codex 异常退出 | 不自动重开（下次点击原版图标时接管） | ✅ 行为同上（实现层面一致） |
| 重复启动监督进程 | 第二个守护因互斥退出，监督进程退避 60 秒 | ✅ `guard.already-running` |
| 连续点击原版图标 | 单实例，聚焦已打开窗口，不重复启动 | ✅（应用自身单实例机制） |
| 守护进程被强杀 | 监督进程 3 秒内拉起新守护 | ✅ `supervisor.restart` |
| 中途关闭 Codex 后再点原版图标 | 守护接管并切换中文（约 20～40 秒） | ✅ `guard.takeover` |
| Windows 注销 / 重启 | 自启项重新运行 | ✅ 用户实测通过（2026-10-19 用户反馈，见 FUNCTIONAL_TESTS T7）；模拟登录验证亦通过 |
| 更新过程中退出程序 | 旧版本保留、可回滚 | ✅ 见 `UPDATE_AND_ROLLBACK.md` |

## 3. 权限边界

- 全程无需管理员权限（仅写 HKCU 与当前用户证书/文件）。
- 自启动项：`HKCU\...\Run` 中的 `CodexZhLauncherZh = "<exe>" --supervise`，用途为后台守护。
- 进程参数中不含账号、Token 等敏感信息。
- 日志写入前会脱敏用户目录（见 `PRIVACY_AND_NETWORK.md`）。
